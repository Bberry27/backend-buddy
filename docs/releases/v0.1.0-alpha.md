# Backend Buddy v0.1.0-alpha

The first tagged release. **Alpha**: it runs, it is useful against a real database, and several
views are not finished. Read section 3 before showing it to anyone who will judge the product by it.

Semantic version `0.1.0-alpha`, from `package.json`. The changelog section for this release is
[`CHANGELOG.md`](../../CHANGELOG.md) `[0.1.0-alpha]`; every line there carries the work-package or
feature id that delivered it.

---

## 1. What works

A person can run one container, open one URL, type database credentials into a form, test the
connection, populate the schema, measure it, and explore it in thirteen linked views. That path is
verified end to end against a real PostgreSQL 16.

| Area | State |
|---|---|
| Single-port Docker deployment (`npm run up`) | Credentials entered in a browser and encrypted on disk, persisted in a volume. One command. |
| Local admin area | Connections list, credential form, test, populate structure, measure row counts, gather column statistics, delete. |
| Catalog introspection (PostgreSQL) | Tables, views with definitions, columns, keys, constraints, indexes, declared foreign keys. Metadata only; no table is queried. |
| Row counts | A separate, consented action: exact `count(*)` per table, merged into the snapshot. No column value is read. |
| Column statistics | A second consented action: null fractions and distinct counts over the whole table, with extremes retained only for numeric and temporal types. No row and no sample value is retained. |
| Thirteen views | Four host views and nine React views over one selection and one inspector. |
| Offline artifact | One self-contained HTML file behind `connect-src 'none'`; opens from a file share with no server. |
| Contract | Versioned JSON Schema, TypeScript generated from it, drift checked in `npm test`. |

**Schema City**, **Column Table**, **Relational map**, **Entity index**, **PK / FK index**,
**Join Matrix**, **Arc Diagram** and **Domains** are the views to demonstrate. Schema City in
particular is worth seeing after measuring row counts: buildings are sized by the log of a measured
count, and the difference between an empty table and a five-million-row one is the whole point.

## 2. Upgrading

Nothing to do beyond pulling and `npm run up`. From this release the container notices when its
views are newer than the page it is serving and re-renders your populated schema on start, so an
upgrade no longer leaves an older interface on screen. Your data is untouched by that; only the
picture is redrawn.

## 3. Known incomplete — read before demonstrating

These ship in the release and are reachable from the tab bar. They work in the sense that they
render and do not fail, but each needs further work before it represents the product:

| View | What is not finished |
|---|---|
| **Row fan-out** | Opens on a sensible root and explains an empty one, but "Start from one row" needs a live subtree connection that cannot be reached through a published container port (work package S03). Ratios read *Unavailable* wherever a row count is missing, and the fan-out covers declared non-unique foreign keys only. |
| **Living ERD** | Four zoom tiers, in-place domain expansion and cross-domain ribbons landed this release, but layout quality on large schemas, edge routing and the drill-through contract with the other views are unfinished. |
| **Normalization Lens** | Candidate detection is implemented against the pure logic modules; the findings are not yet reviewed against real schemas, and the presentation of evidence needs work. |
| **Normalization review** | The review workflow records decisions and exports CSV, but the finding set, its wording and the next-validation-step SQL have not been exercised beyond fixtures. |
| **Schema Diff** | Compares two snapshots and classifies changes, but there is no way to choose the two snapshots from the interface, and the change taxonomy is not settled. |

Treat all five as previews. The eight views listed at the end of section 1 are the ones that carry
the demonstration.

### Interface change already decided

The **admin connection manager is a separate page that nothing links to from the explorer**. That is
temporary. It will be relocated to a control on the main page so connections are managed where the
schema is read, rather than at a URL a user has to be told about. The current separation is an
artefact of the admin area being server-rendered and the explorer being a static artifact; do not
build anything that depends on the two being separate.

## 4. Other limits in this release

- **PostgreSQL only.** No MySQL, SQL Server, Oracle or SQLite target from the admin area.
- **Single tenant, single machine.** No API, no metadata database, no sessions, no audit trail, no
  multi-user access. Connections live encrypted in a Docker volume on the machine that created them
  and do not travel.
- **Sample values are not offered anywhere.** They are the one profiling output that puts real row
  content on screen and they need a per-connection and per-request opt-in that is not built.
- **No browser, accessibility, performance or visual-regression gate.** Six Playwright suites exist
  and are not wired into CI (work package S02), so interaction behaviour is verified by hand.
- **Row counts and statistics are a snapshot, not a feed.** Re-run the actions to refresh them;
  nothing schedules them.
- **The licence is a draft** pending legal review, and names an account handle rather than a legal
  person. See [`LICENSE`](../../LICENSE).

## 5. Security and licensing notes

- Open findings, if any, are listed in the Security section of [`CHANGELOG.md`](../../CHANGELOG.md).
  The S01 hardening package closed the artifact and renderer findings, each pinned by a named
  regression test.
- Third-party components are listed in
  [`THIRD_PARTY_NOTICES.md`](../../THIRD_PARTY_NOTICES.md), which is generated and drift-checked in
  CI. `cryptography` and `psycopg` ship inside the container image; `psycopg` is LGPL-3.0-or-later
  and used as a separately installed, replaceable component, and `cryptography` is offered under
  Apache-2.0 **or** BSD-3-Clause at the recipient's choice. Binary wheels carry components their own
  publishers redistribute, which the notices describe per package.
- `cryptography` is pinned at `>=50,<51`. The audit that first covered it found six advisories
  against the 46.0.7 the image had been shipping; all are fixed at the new floor. Do not lower it.
- Credentials are encrypted with AES-256-GCM under a key held only on the machine that entered them.
  No page renders a password, a certificate body, or ciphertext.

## 6. Verification for this release

```sh
npm run restore
python -m pip install -r packages/profiler/requirements.txt
python -m pip install -r tools/local_admin/requirements.txt
npm run guard
npm test
npm run notices:check
npm run build && test -s dist/backend-buddy.html && grep -q "connect-src 'none'" dist/backend-buddy.html
```

At the time of writing this release, that is 175 TypeScript unit tests, 51 profiler, 40 renderer,
17 contract, 10 fixture and 47 admin tests, with 117 script tests from `npm run test:scripts`.
Seven admin tests need a real PostgreSQL and skip without `BB_TEST_ADMIN_DSN`.

`scripts/verify_host.mjs` is **not** part of this verification: it needs a Playwright runtime that
the project does not yet pin (S02).
