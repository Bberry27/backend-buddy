# ADR-0007: Private-data and fixture policy

- **ADR status**: proposed
- **Date**: 2026-09-07
- **Deciders**: Product owner, Security lead, Platform lead
- **Work packages**: R00, R01, S02, Q05
- **Related**: ADR-0001, ADR-0006, `docs/README.md` (private data rule), `docs/architecture/legacy-handoff.md`, F22

## Context

The product was extracted from a working copy that contained one private example project: its schema snapshot, an adapter with internal domain and alias knowledge, archived artifacts and QA evidence, and its name in prose, a test template filename, and a QA harness with hardcoded row and column counts. The plan lists these carriers and requires that none enter the new repository; the docs rule is that the example is referred to only as "the original private example" (`docs/README.md`).

State in the new repository (verified):

- `.gitignore` excludes `/reference/`, `/examples/`, `dist/`, `skill/assets/extensions/dist/`, `.qa/`, `outputs/`, `playwright-report/`, `test-results/`, `.env*` except `.env.example`, `*.key`, `*.pem`.
- `scripts/private_data_guard.mjs` (R00) enforces: no tracked path under `reference/` or `examples/` or under `dist/`, `.qa/`, `outputs/`; no images outside `docs/assets/`; no `report.json`; no file over 2 MB unless allowlisted in `scripts/private_data_guard.allow`; no Windows user paths, agent-local dot-directory paths, or Unix home paths in text; an optional local denylist from `BB_DENYLIST_FILE` that must live outside the tree and is never printed. It runs in CI (`.github/workflows/ci.yml`, job `guard`) and pre-commit (`.githooks/pre-commit`, `scripts/install-hooks.mjs`).
- `scripts/project.mjs:89` builds from `fixtures/schemas/medium.json` by default with `--schema` and `BB_SCHEMA` overrides. `fixtures/` exists (R01): `fixtures/schemas/{small,medium,medium-measured,edge-cases,many-domains,hostile,empty}.json`, `fixtures/contract/{valid,invalid}/*.json`, `fixtures/sql/{pg,sqlite}/seed.sql`, `fixtures/test_fixtures_normalize.py`, and `fixtures/README.md`; everything except the README, `fixtures/.gitignore`, and the Python test is generated by `scripts/generate-fixtures.mjs`. `fixtures/schemas/large.json` is not committed: it is above the 2 MB cap, git-ignored (`fixtures/.gitignore`), and generated on demand with `--large` (`scripts/generate-fixtures.mjs:17-20`).
- `packages/explorer/server/test_explorer_http.py:29` resolves a neutral template filename with fallbacks (`:30-33`).
- `scripts/verify_host.mjs` derives its eight count assertions from the embedded snapshot (`report.schema`, read through `window.schemaSnapshot()`) since the R00 fix round; `scripts/verify_host.test.mjs` fails if a count literal returns. S02 adds the `--schema` cross-check and the remaining parameterisation. The fixture tests read the locally forbidden counts from `BB_FORBIDDEN_COUNTS` (never committed) so that the repository does not name them either.
- `docs/architecture/legacy-handoff.md` stated the private example's counts in prose (section "Source and Data Boundaries"); the sentence was rewritten without numbers during D02, and the file now carries no counts.
- The security workflow runs gitleaks with default rules, `npm audit --omit=dev --audit-level=high`, and pip-audit (`.github/workflows/security.yml`); the gitleaks Action is not used because the private-name rule must never be committed.

Forces:

- A single leaked name or count in a fixture, test, or doc is a licensing and confidentiality problem for a product that will be shared with licensees.
- Tests and QA need realistic schemas with measured counts, composite keys, cycles, missing metadata, many domains, and hostile strings (CTQ-01, CTQ-07, CTQ-09), none of which may come from the private example.
- The owner keeps using the private snapshot locally (`--schema` flag) without that ever appearing in the repo.

## Decision

1. **Never in the repository or images**: the private example's schema, adapter, artifacts, QA evidence, name, and counts. Paths `reference/` and `examples/` are ignored and guarded; `.dockerignore` mirrors `.gitignore` (O01); image contents are listed in CI (CTQ-14).
2. **Repo-neutral guard, local denylist**: `scripts/private_data_guard.mjs` runs on every commit and in CI with rules that name no private term; the name denylist runs only locally from `BB_DENYLIST_FILE` outside the tree. A gitleaks rule containing the name is never committed.
3. **Synthetic fixtures only** (R01): seeded `scripts/generate-fixtures.mjs` produces `fixtures/schemas/{small,medium,medium-measured,large,edge-cases,many-domains,hostile,empty}.json` (`large` generated on demand and git-ignored; medium about 8 domains and about 160 tables with views, composite keys, inferred links, an SCC cycle, tables without PK; measured variant with `rowCount 0` for some tables, `rowCountLowerBound`, sampled flags), `fixtures/sql/{sqlite,pg}/seed.sql` via `schema-diff-logic.tableDDL` (`packages/explorer/src/schema-diff-logic.ts:284`), and `fixtures/contract/{valid,invalid}`. No fixture is named after or sized to the private example's counts.
4. **Schema-derived assertions**: `scripts/verify_host.mjs` reads counts from the embedded JSON (S02); no test asserts a literal count that originated in the private example.
5. **Prose rule**: documents say "the original private example" when a reference is unavoidable and never state its counts, as product facts or as provenance; the archived legacy handoff is superseded by CTQs (its end note) and follows the same rule with no exception.
6. **Two build modes**: the repository builds only from `fixtures/`; the owner's local copy may pass `--schema <private path>` or `BB_SCHEMA`, and neither the path nor the file is committed (guard rule for Windows user paths catches accidental prose).
7. **Hostile fixture**: `fixtures/schemas/hostile.json` carries XSS, CSV formula, SQL identifier, bidi/zero-width, prototype-key (`constructor`, `__proto__`), and oversize strings for S01/Q02 tests; it is the only fixture allowed to contain markup-like text.

## Consequences

- Positive: CI can build and test from a clean clone; licensees receive a repository free of another customer's data; every count in tests is derived, so fixtures can change freely.
- Negative: synthetic fixtures must be maintained and made realistic enough to exercise layout and performance paths (City to 600 tables today, 1000+ post-MVP); the local denylist is a per-developer setup step (`docs/developer/setup.md`, D07).

## Alternatives considered

- Anonymise the private snapshot (rename tables and columns) and commit it: rejected; structure, domain vocabulary, and counts remain identifying and licensing-sensitive.
- Commit the denylist with the guard: rejected; the denylist would itself carry the name.
- Rely on `.gitignore` alone: rejected; ignore rules do not catch names in prose, filenames, or constants, and the baseline's ignore file missed the adapter directory (plan).
- Do nothing (build from the private file as before): rejected; `npm run build` would fail from a clean clone and CI could never run.

## CTQs affected

- CTQ-14 private-data hygiene: guard green every commit; image contents listed.
- CTQ-01, CTQ-09: `medium-measured` and `large` fixtures make unknown-vs-zero and performance measurable without private data.
- CTQ-07: `hostile` fixture drives injection tests.
- CTQ-13: docs lint checks that no document names the private example (rule expressed as the local denylist plus the prose convention).

## Verification

- R00: `npm run guard` green; `scripts/private_data_guard.test.mjs`; `git ls-files` contains nothing under `reference/` or `examples/`, no PNG, no `report.json` (Gate G1).
- R01: `npm run fixtures` regenerates byte-identical fixtures from the seed; `fixtures/` unit tests validate every fixture with `normalize()` and `parseSchemaSnapshot` (`schema-diff-logic.ts:39`).
- S02: `scripts/verify_host.mjs` has zero literal count assertions; counts come from `window.schemaSnapshot()` (`skill/assets/explorer.html:191`).
- O01: image file listing in CI shows no `reference/`, `examples/`, `.qa/`, `dist/backend-buddy.html`.
- Q05: docs lint runs the local denylist when `BB_DENYLIST_FILE` is set; CI runs the repo-neutral rules.
