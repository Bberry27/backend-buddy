## 1. Purpose

The offline artifact is one self-contained HTML file that holds the host shell, the React view bundle, the icons, and one schema snapshot, and runs from `file://` with a frozen Content Security Policy and zero network requests. The skill is the portable `skill/` directory that lets an agent (or a person with Python only) validate a snapshot and render that artifact for any project without Node. Together they are the export path of the product and the thing existing users already have; they are not the SPA, they hold no credentials, and they never connect to a database unless a person starts the separate loopback server with an explicitly selected read-only connection.

## 2. Driver

- **Persona**: P1 architect and P5 engineering manager (share a schema review without deploying anything), P6 licensee security reviewer (a file with no network surface is easy to approve), P3 backend developer (agent-driven generation in a repository) (definitions in `docs/business/business-case.md`, D01).
- **Job to be done**: "Give me one file I can open, attach to a ticket, or hand to a reviewer, that shows the whole schema and never phones home."
- **Business metric**: to be validated (business case D01 in progress). Candidate: number of artifacts exported per active project.

## 4. Intended behaviour

### MVP

- **B1** The artifact keeps working from `file://` with the CSP byte-identical to today's string and zero network requests (D9, CTQ-05); `scripts/verify_host.mjs` asserts both on every build in CI.

The 9 existing renderer tests stay green unchanged.
- **B3** Host hardening (S01): `${t.line}` escaped at `:77`; `tableSQL` at `:108`/`:110`; dialect-gated JSON draft; `Object.hasOwn` for `colors[t.type]`; CSV guard for `= + - @ \t \r` after leading whitespace; `render()` unmounts only when the view id changes.

## 5. Drill-through contract

Reference: `docs/architecture/drill-through-contract.md` (ADR-0005, D02). The artifact hosts all 13 views, so every view's contract applies; this section covers the host's role.

### Inbound

- Today: no URL or hash state; the host holds `state.selected` and passes only `onSelectTable`/`onSelectTables` to React views (`explorer.html:195`).
- MVP: the artifact shell adopts the shared `Selection` store and `route-state.ts` parsing of `location.hash` so a view mounted inside the artifact receives `selected` like in the SPA (C03); deep links via hash are L-05.

### Outbound

- Views emit `onSelectTable`, `onSelectTables` (today), and the C03 additive callbacks (MVP); the host routes them to the inspector and, for `onNavigate`, switches tabs and carries the selection.
- Rule: a drill-through may prefill a live query but never runs it without a click; in the offline artifact there is no live connection at all (`connect-src 'none'`).

### URL state

- Offline artifact: query strings do not apply to `file://` reliably; the hash carries the same grammar (`t c r ts f q d k v.*`) once L-05 lands. Until then nothing is in the URL.
- Not in the hash: theme (localStorage, `:53-56`), decisions (localStorage), camera and pan (`viewState` slice in localStorage keyed by `project.key` and graph fingerprint, C13).

## 6. Data contract dependencies

The artifact consumes the whole SchemaGraph. Since C01 the field set is declared in `packages/contract/schema-graph.v1.json`, generated into `packages/explorer/src/contract.generated.ts`, and re-exported by `packages/explorer/src/types.ts`; the nine views compile against it unchanged. Renderer-enforced fields and defaults are listed in section 3. The fields that used to reach the views only through the index signature are now typed and structurally validated: `kind`, `definition`, `checks`, `file`, `line`, `rowCount`, `rowCountLowerBound`, `rowCountExact`, `sampleSize`, `sampled`, `profiling` (with `status` and `reason`), `sampleValues`, `typeDefinition`, `default`, `serverDefault`, `applicationDefault` and `cardinality`. `normalize()` still owns the semantic rules and is imported, never copied. The index signatures on `SchemaGraph`, `SchemaTable`, `SchemaSource` and both profiling types stay, so a minor version's unknown fields keep passing through. `LiveConnection` methods `profile` and `subtree` exist only in the served copy (`explorer.html:189`), never in the file.

## 7. Caveats

> C04: "Migration SQL and validation SQL are drafts for human review. The product never executes them, never offers a control that executes them, and never opens a database connection on their behalf."
> Shown: the artifact has `connect-src 'none'` (`explorer.html:6`) and no SQL-executing control; SQL drafts are text in F04 and F10 with their labels.

> C09: "A source checkout, ORM model, or stored snapshot documents a schema at one point in time. It is not proof of the live database schema. "Declared" means declared in the identified evidence source, not verified against a live catalog, unless the snapshot's provenance says so."
> Shown: provenance footer (`:58-59`: text at `:58`, `source.basis` as `title` at `:59`), status footer `Snapshot only` versus `Live read-only connection` (`:178`), inspector `Source & scope` block (`:77`); `normalize()` default basis text `Source coverage not specified by adapter; not verified against a live database.` (`build_explorer.py:30`).

> C13: "Browser storage holds convenience state only: theme, layouts, camera, and local decisions. It is not a team review database. Every stored key is scoped by the project's stable key (and, where the data depends on the schema, by the snapshot fingerprint) so that different projects and environments never read or overwrite each other's state."
> Shown: storage prefix `backend-buddy:<project.key>` (`:39`) and the `project.key` regex (`build_explorer.py:24`) that prevents key collisions; storage-failure toast (`:79`); `skill/SKILL.md` step 4 instruction on a stable `project.key`.

> C14: "The product never discovers or connects to a database implicitly, and never to production to make a view look populated. Live access uses only a connection the user explicitly selected, opened read-only with bounded queries, and a metadata request never authorizes scanning customer rows."
> Shown: `serve_explorer.py` requires `--dialect` plus `--database` or `--dsn-env` (`:31-37`), never creates a database (`:22`), uses `connect_readonly` (`:93`), and the offline file cannot connect at all; `skill/SKILL.md` "Advanced Views and Profiling" paragraph; MVP `SKILL.md` text uses the canonical string.

## 10. Security and privacy

- Inputs: a snapshot JSON (validated by `normalize()`, MVP also by JSON Schema); repo-built bundle and CSS (escaped in `render()`, B2); for the server, JSON bodies capped at 64 KiB (`serve_explorer.py:83-85`).
- Rendering: all schema text is escaped by `E()` except the `:77` sink (S01); after W03 the host renderers are replaced by React components.
- Storage: `backend-buddy:<project.key>:{theme,reviews}` and view-state slices (C13). No credentials anywhere in the artifact; the DSN is read from an environment variable by the server only (`:35`).
- Exports: the snapshot JSON export (`:180`) contains whatever the snapshot contains, including `profiling` and `sampleValues` if present; MVP export path strips `sampleValues` and string min/max by default (B8, F19).
- Network: none in the file (CTQ-05); the served copy allows same-origin only and stays on loopback or the allowlisted bind (B6).
- CTQ-07 checks: hostile fixture through the artifact, CSP byte check, bundle grep for secrets, `npm audit --omit=dev`, pip-audit; CTQ-14: guard on every commit; the private example is never named in the skill or its tests (`test_explorer_http.py:29` uses a neutral template name).

### C01 contract v1 (2026-09-08)

`packages/contract/schema-graph.v1.json` is now the single source of truth for the SchemaGraph
field set, and both sides of the product are generated from or validated against it:

- `scripts/gen_contract.mjs` generates `packages/explorer/src/contract.generated.ts` (committed,
  so the skill copy builds without the generator), the field tables in
  `skill/references/schema-contract.md`, and Part A of
  `docs/architecture/schema-graph-contract.md`, which reproduces that reference verbatim;
  `npm run contract:check` compares all three and runs inside `npm test`.
- `packages/explorer/src/types.ts` re-exports the ten generated interfaces and keeps only
  `SubtreeResult`, `ProfileResult`, `LiveConnection` and `ViewProps` by hand. No view changed.
- `packages/profiler/bb_profiler/contract.py` validates a document with `jsonschema` and then
  runs `build_explorer.normalize()` as the semantic oracle, imported by path and never copied.
- The shared corpus grew by three valid and four invalid contract v1 documents in
  `fixtures/contract/v1/`, and each invalid document now records which stage rejects it, so both
  test suites can assert that the structural and semantic stages partition the corpus.
