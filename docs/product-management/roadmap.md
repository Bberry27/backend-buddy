Work packages are identified by track letter: **D** docs, **R** repo, **S** security and hardening, **C** contract and core, **W** web, **A** API, **O** ops, **Q** quality. Every work package has (or will have, D08) a brief at `docs/product-management/agent-briefs/WP-<id>.md`. No dates are given: the owner sets them at each gate. Phase 0 packages run in parallel, so the Status column is a snapshot: statuses were re-verified on 2026-09-07 after R00 and R01 landed, and `landed` says nothing about review state (every document is still `draft`).

### Schema City MVP (W05)

Intent, as approved: the orientation view for large schemas: districts are domains (declared or discovered), footprint is column count, height is log row count, roads are FKs. It answers "where is the mass, what is unprofiled, what crosses domain boundaries" and hands the user to detail views. It never fabricates counts, keeps a flat accessible mode, and must stay readable to 1,000+ tables (perf work post-MVP).

1. Unknown-rows banner + profile action (`role=status`, "Profile visible tables" enabled only when `live?.profile` exists; heights update without remount; legend shows "sampled").
2. Search / focus-on-table (`role=combobox`; Enter selects and flies within 600 ms; instant under reduced motion; flat mode pans).
3. Inbound selection + highlight + fly-to (`selected.tableId` drives label priority and an outline mesh; `.schema-city [data-selected="true"]`; flat rect has `is-selected`).
4. District labels in scene (`placeCityLabels` gains `kind:'district'|'table'`).
5. Palette >= 12, colour-vision-safe, deterministic, light/dark (`domainColor(...)` replaces `COLORS[index % 7]` at `city-layout.ts:194`; roof-stripe variant beyond 12 hues).
6. Inspectable roads (enable raycast, wider invisible hit mesh; tooltip with the C02 volume-proxy wording; click -> `onSelectRelationship`).
7. Keyboard table-list drawer in 3D mode (flat mode remains the AA path).
8. View state: 3D/flat mode and district grouping persisted per snapshot via `viewState`; camera in localStorage (C13).
9. No remount on filter change; selection no longer cleared at `City.tsx:309` when only filters change.

## MVP definition

Verbatim from the approved plan:

> a licensee admin runs `docker compose up` from a clean clone, bootstraps the first owner, creates a workspace and project, uploads a snapshot or registers a read-only PostgreSQL/SQLite connection (encrypted, never returned), tests it, extracts the catalog into an immutable snapshot, profiles selected tables with partial results, navigates all 13 views plus Insights v0 with bidirectional deep-linkable drill-through and a persistent inspector, uses the completed Schema City MVP, records review decisions server-side, exports CSV/SVG/PNG and the offline artifact, sees an audit trail, and can roll back by image tag + Alembic downgrade.
