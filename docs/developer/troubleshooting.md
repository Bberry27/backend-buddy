# Troubleshooting

Symptoms, causes, and fixes for the problems a developer meets with the current tree. Each entry names the code that produces the behaviour so the fix can be checked rather than guessed. If your problem is not here, look at the exit code and the last command `scripts/project.mjs` printed: it runs child processes with inherited output and exits with the child's status (`scripts/project.mjs:14-18`).

## Python interpreter

**Symptom** `npm run build` or `npm test` dies with `spawnSync python ENOENT` (or `python3 ENOENT`), or the wrong Python runs.

**Cause** `scripts/project.mjs:10` resolves the interpreter as `process.env.PYTHON`, else `python` on Windows and `python3` everywhere else, and `run()` rethrows the spawn error (`:16`). Debian and Ubuntu images ship only `python3`; some Windows setups have only the `py` launcher; virtual environments are not detected.

**Fix** Set `PYTHON` to the interpreter you want, an absolute path if necessary:

```sh
export PYTHON=python3                       # bash/zsh
$env:PYTHON = 'python'                      # PowerShell
export PYTHON="$PWD/.venv/bin/python"       # a venv
```

CI sets `PYTHON=python3` globally (`.github/workflows/ci.yml`, top-level `env`). Python 3.13 is the supported version; apart from the `jsonschema` that `bb_profiler` requires, the code uses only the standard library, so an older 3.x usually works, but do not rely on it.

## `Run through npm run build or npm test.`

**Symptom** `node scripts/project.mjs build` (or `test`) throws `Error: Run through npm run build or npm test.`

**Cause** `scripts/project.mjs:8` reads `process.env.npm_execpath`, which only npm sets, and `npm()` throws when it is missing (`:19-20`) because it re-invokes npm to run the explorer package scripts (`:21`).

**Fix** Always use the npm scripts: `npm run build`, `npm test`. In a container `CMD`, a Makefile, or a task runner, call `npm run build`, not the script file. Passing arguments works through npm's `--` separator: `npm run build -- --schema path/to/schema.json`.

## Missing fixtures

**Symptom** `npm run build` ends with a Python traceback `FileNotFoundError: ... fixtures/schemas/medium.json`, or `npm test` prints `fixtures/: no test_*.py files yet; skipping unittest discovery.`

**Cause** The default build input is `fixtures/schemas/medium.json` (`scripts/project.mjs:89`), read by `skill/scripts/build_explorer.py:118`. The `fixtures/` tree is generated by `scripts/generate-fixtures.mjs` (`npm run fixtures`, work package R01) and is committed, except `fixtures/schemas/large.json`, which is git-ignored above the 2 MB cap (`fixtures/.gitignore`) and written only with `--large`. The symptom therefore means the file was deleted locally or the checkout predates R01. The test skip line comes from `scripts/project.mjs:109-113` and appears only when `fixtures/test_*.py` is absent; with `fixtures/test_fixtures_normalize.py` present, step 5 runs.

**Fix** `npm run fixtures`, then build. To build against a snapshot kept outside the clone use `npm run build -- --schema <path>` or `BB_SCHEMA=<path> npm run build` (`schemaArgument()`, `scripts/project.mjs:87-93`; a bare `--schema` with no value is rejected at `:91`). Never copy a snapshot into the repository to get past this; the guard rejects `examples/` and `reference/`, and a real snapshot is private data.

## Nine tabs read "Extension bundle unavailable"

**Symptom** `dist/backend-buddy.html` opens, the four host views work, and every React tab shows "Extension bundle unavailable".

**Cause** The renderer substitutes empty strings when `skill/assets/extensions/dist/extensions.js` or `.css` is missing instead of failing (`skill/scripts/build_explorer.py:104-106`); the host then prints the message at `skill/assets/explorer.html:194`. This happens when `build_explorer.py` is run directly before `npm run build` has produced the bundle and `syncSkill()` has mirrored it (`scripts/project.mjs:98-99`).

**Fix** Run `npm run build`, which performs the esbuild bundle, the mirror, and the render in order. Confirm `packages/explorer/dist/extensions.js` and `skill/assets/extensions/dist/extensions.js` exist. S01 considers making the renderer fail loudly; until then this silent degradation is a known behaviour of the portable skill.

## WebGL, swiftshader, and headless browsers

**Symptom** Schema City is blank in a headless browser, or the 3D suite fails with a WebGL context error, or the City canvas is black on a machine without a GPU.

**Cause** Headless Chromium without a GPU has no hardware WebGL. The suites that touch City launch with `--use-angle=swiftshader --enable-unsafe-swiftshader` for software rendering (`packages/explorer/src/city-browser.test.mjs:53`, `scripts/verify_host.mjs:40`). `skill/scripts/check_explorer.cjs` and `skill/scripts/check_map_pan.cjs` pass no such flags, so they cannot exercise City without a GPU.

**Fix** Add the two flags to any Playwright launch that renders City. To test the accessible fallback instead, launch with `--use-gl=disabled`: the City probes WebGL once, shows "WebGL unavailable · Flat map active", and disables the 3D button (CTQ-04; `verify_host.mjs:334` exercises this path). Under swiftshader, pixel and frame-time assertions are slower and noisier; the plan calibrates baselines on medians over 60 frames before enforcing budgets (CTQ-09).

**Symptom** A browser suite fails to launch with a message about `msedge` not being installed.

**Cause** `column-browser.test.ts:43` and `schema-diff-browser.test.ts:26` hardcode `channel: 'msedge'`; `fanout-browser.test.mjs:22` and `living-browser.test.mjs:26` default to it with `|| 'msedge'`, so an empty string still selects Edge.

**Fix** For fanout and living set `FANOUT_BROWSER_CHANNEL=chromium` or `LIVING_BROWSER_CHANNEL=chromium` (any installed channel). The two `.ts` suites need Edge until S02 removes the hardcoding; skip them (leave their `*_PLAYWRIGHT_PATH` unset) on machines without Edge.

## Playwright not found

**Symptom** `Cannot find module 'playwright'` (or `pngjs`) from a browser suite or `skill/scripts/check_*.cjs`; `verify_host: cannot find "playwright"` with exit code 2 from `scripts/verify_host.mjs`.

**Cause** Playwright and pngjs are not dependencies of any package in the repository at the commit in the status header. Each script resolves them from an env var or a bare `require` (table in `docs/developer/test.md`, section 5.2); `verify_host.mjs` checks for them up front and prints instructions instead of a stack trace.

**Fix** Install a runtime outside the clone and point the suite's env var at it (`CITY_BROWSER_MODULES`, `DEPENDENCY_BROWSER_MODULES`, `*_PLAYWRIGHT_PATH`, `*_PLAYWRIGHT_MODULE`), or expose it through `NODE_PATH` for the bare `require` scripts. Do not add it to `package.json` outside S02, which pins it deliberately.

## Live mode: 404 on `http://localhost:8765/`

**Symptom** `serve_explorer.py` is running, but the browser gets an empty 404, or `POST /api/...` returns `403 {"error":"Invalid origin"}`.

**Cause** The server accepts only `Host: 127.0.0.1:<port>` (`packages/explorer/server/serve_explorer.py:42`, `:58-59`, `:62`) and, on `POST`, `Origin: http://127.0.0.1:<port>` (`:75`). `localhost`, a different port (for example a Docker published port mapping), or a hostname all fail; the tests pin `localhost` as rejected (`test_explorer_http.py:206`, `:220`).

**Fix** Open exactly the URL the server prints (`:114`). Work package S03 adds `--bind` and `--allowed-hosts` (default allows `localhost:<port>`) and moves the token into a cookie; until then live mode does not work through a container port.

**Symptom** `403 {"error":"Read-only connection unavailable"}` on every profile request.

**Cause** The server was started without `--dialect`, or the page was opened from `file://` rather than from the server, so no capability token is present (`serve_explorer.py:79`, `skill/assets/explorer.html:187-188`).

**Fix** Start with `--dialect sqlite --database <file>` or `--dialect postgresql --dsn-env <NAME>`, and load the page from the server URL.

**Symptom** `409 {"error":"A read-only job is already running"}`.

**Cause** Single-flight lock (`serve_explorer.py:89-90`). **Fix** Wait for the running job; the lock releases when it finishes or hits the 5 s deadline.

## SQLite database "not found" or "requires an explicit existing file path"

**Cause** The profiler resolves `--database` strictly and never creates a file (`packages/explorer/server/schema_profiler.py:193-195`); `:memory:` is refused. Inside a container the path must exist at the same path inside the container; `~` expands to the container user's home.

**Fix** Create the database first (`docs/developer/run.md`, 3.1) and pass a path that exists where the process runs.

## PostgreSQL: `ModuleNotFoundError: No module named 'psycopg'` or "requires explicit host, dbname, user, password"

**Cause** psycopg is imported only when a PostgreSQL connection is opened (`schema_profiler.py:205-206`) and is not installed by default. DSNs must name all four fields and may not use `service` or `passfile` (`:208-214`).

**Fix** `python -m pip install -r packages/explorer/server/requirements.txt`; put a complete DSN in an environment variable and pass its name with `--dsn-env`. The value is never accepted on the command line.

## Guard failures

**Symptom** `private-data guard: FAILED - N violations ...`, listing rules such as `content:windows-user-path`, `path:image-outside-docs-assets`, `path:report-json`, `path:coverage-data`, `path:oversize`, or `denylist#N`.

**Cause and fix** Each rule is described at `scripts/private_data_guard.mjs:9-24`. Typical cases: a pasted absolute path in a document (replace it with a repository-relative path or a generic example), a screenshot or `report.json` from a QA run left in the tree (delete it, or move a synthetic-fixture screenshot under `docs/assets/`), a file over 2 MB (regenerate smaller, or, with review approval, list it in `scripts/private_data_guard.allow`), a denylist match (remove the private name; the guard masks the match and never prints the pattern).

**Symptom** exit code 2: `BB_DENYLIST_FILE must point outside the repository ...` or `line N: invalid regular expression`.

**Cause** The guard refuses to read a denylist inside the scanned tree (`:163-169`) and rejects invalid regexes without echoing them (`:184-187`). **Fix** Move the file outside the clone; fix the regex on the reported line.

**Symptom** the guard passes locally and fails in CI, or vice versa.

**Cause** Without a `.git` entry the guard walks the filesystem; with one it uses `git ls-files` including untracked, non-ignored files (`:228-243`). A file ignored locally but force-added, or present only in the working tree, differs between the two modes. **Fix** Run `npm run guard -- --list-only` to see what is scanned in your mode.

## Engine check: `EBADENGINE` warning or refusal

**Symptom** `npm run restore` prints `npm WARN EBADENGINE Unsupported engine` and completes anyway, or an npm command run at the repository root refuses with an `EBADENGINE` error.

**Cause** Both `package.json` files declare `node >=22`, `npm >=10.5.1`. The root `.npmrc` sets `engine-strict=true`, but `restore` is `npm --prefix packages/explorer ci` (`package.json:12`) and npm reads the project `.npmrc` from the prefix directory, where none exists; `npm --prefix packages/explorer config get engine-strict` prints `false` while the root prints `true`. So the explorer install on an unsupported Node warns and completes, and only root-level commands are refused.

**Fix** Switch to Node 22 (`nvm use` reads `.nvmrc`), then `npm run restore`. Do not treat an install that completed with the warning as supported; the toolchain is tested on Node 22 only. Making `restore` strict (a `packages/explorer/.npmrc`, or `--engine-strict` on the script) is an open R00 item.

## `node --test scripts/` fails on Node 22

**Cause** Node 22 treats a bare directory argument as a module. **Fix** Use `npm run test:scripts`, which passes the glob `"scripts/**/*.test.mjs"` (`package.json:16`); CI's `scripts` job runs the same npm script after `npm run restore` (`.github/workflows/ci.yml`, job `scripts`). Script tests end with `.test.mjs` and may live at any depth under `scripts/`; other suffixes are not discovered, and `scripts/repo_consistency.test.mjs` fails when one appears.

## Windows specifics

- **Line endings**: `.gitattributes` normalises everything to LF (`* text=auto eol=lf`). If a diff shows every line changed, your editor saved CRLF; re-save as LF (`.editorconfig` asks for it) and do not set `core.autocrlf=true` for this clone.
- **Hooks**: NTFS has no executable bit. Git for Windows runs `.githooks/pre-commit` through its bundled `sh`, so `npm run hooks` needs no `chmod` there; on Linux and macOS the script sets the bit (`scripts/install-hooks.mjs:68-74`). The tracked mode is kept at `100755` with `git update-index --chmod=+x .githooks/pre-commit`.
- **`python` versus `py`**: if only the `py` launcher is on `PATH`, set `PYTHON=py` (arguments pass through unchanged).
- **Shell quoting**: in bash and zsh quote the unittest pattern (`-p 'test_*.py'`); PowerShell does not glob-expand bare `*`, so quotes are optional there. PowerShell 5.1 does not support `&&`; chain with `;` or run commands separately.
- **Paths in prose and file names**: never paste a path starting with a drive letter and the `Users` folder into a document; the guard rejects it (`content:windows-user-path`) and the CI runner would reject the file name (`path:windows-drive-letter`). Two guard tests skip on Windows because NTFS cannot create names containing a colon and symlinks need elevated rights; the skip reason is printed.
- **Antivirus and `npm ci`**: real-time scanning can slow large installs such as `packages/explorer/node_modules` (not measured for this repository). Excluding the clone's `node_modules` from scanning is a local choice; do not commit any workaround.
- **`file://` storage origin**: browser-dependent. Some browsers isolate `localStorage` per local file, others share one `file://` origin across all local files (to be validated per supported browser). Treat theme and review decisions saved from a `file://` artifact as non-portable: moving or renaming `dist/backend-buddy.html` may orphan them. Caveat C13 in `docs/reference/caveats.md` explains why this is acceptable.

## Linux and macOS specifics

- `python3` is the default interpreter name in `scripts/project.mjs:10`; set `PYTHON` if you use a venv.
- `npm run hooks` sets the executable bit on `.githooks/*`; if `git commit` reports the hook is not executable, run `chmod +x .githooks/pre-commit`.
- Headless Chromium needs its system libraries (`npx playwright install --with-deps chromium` in your external runtime) and the swiftshader flags for City.
