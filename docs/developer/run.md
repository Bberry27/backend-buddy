# Running the product locally

Three ways to run what exists today, in order of how often you will need them, then the Compose flow that arrives with work package O01. Prerequisites are in `docs/developer/setup.md`.

## 1. Build the offline artifact from fixtures

```sh
npm run restore     # once
npm run build
```

`npm run build` is `node scripts/project.mjs build` (`package.json`, `scripts.build`) and does three things in order (`scripts/project.mjs:97-103`):

1. `npm run build` inside `packages/explorer` (`packages/explorer/build.mjs`): esbuild bundles `src/index.tsx` into the minified IIFE `packages/explorer/dist/extensions.js` (plus `extensions.css`), global `BackendBuddyViews`.
2. `syncSkill()`: mirrors `packages/explorer/{src,server,dist}` and five config files into `skill/assets/extensions/` (`scripts/project.mjs:52-60`), pruning stale entries. This directory is generated; never edit it.
3. `python skill/scripts/build_explorer.py --schema <schema> --output dist/backend-buddy.html` (`scripts/project.mjs:101`).

The schema input is resolved by `schemaArgument()` (`scripts/project.mjs:87-93`): `--schema <path>` wins, then `BB_SCHEMA`, then the default `fixtures/schemas/medium.json` (`:89`); a bare `--schema` with no value is a usage error (`:91`). Override it with either form; keep any non-fixture snapshot outside the repository:

```sh
npm run build -- --schema path/outside/the/repo/schema.json
BB_SCHEMA=path/outside/the/repo/schema.json npm run build
```

The fixtures directory is generated by `npm run fixtures` (`scripts/generate-fixtures.mjs`, work package R01) and committed, except `fixtures/schemas/large.json`, which exceeds the 2 MB cap, is git-ignored (`fixtures/.gitignore`), and is written only with `--large`. If `fixtures/schemas/medium.json` is missing, `build_explorer.py` fails while reading the schema (`skill/scripts/build_explorer.py:118`); see `docs/developer/troubleshooting.md`, "Missing fixtures".

What the renderer does: `normalize()` validates the SchemaGraph against the contract rules (`skill/scripts/build_explorer.py:21`), `render()` substitutes the five placeholders in `skill/assets/explorer.html` in one pass (`:99-108`), and `main()` refuses identical input and output paths (`:116-117`) and prints a JSON summary `{output, tables, columns}` (`:122`). A successful build prints that one line.

Check the result:

```sh
test -s dist/backend-buddy.html
grep -c "connect-src 'none'" dist/backend-buddy.html     # must be >= 1 (CI does the same check)
```

The artifact must keep the offline CSP byte for byte (decision D9): `default-src 'none'; script-src 'unsafe-inline'; style-src 'unsafe-inline'; img-src data:; connect-src 'none'; base-uri 'none'; form-action 'none'` (`skill/assets/explorer.html:6`).

`dist/` is ignored by `.gitignore` and rejected by the guard; nothing under it is ever committed.

## 2. Open `dist/backend-buddy.html`

Open the file directly in a browser (double-click, or a `file://` URL). No server is needed and the page makes no network requests. All thirteen tabs are available: four host views (map, entities, keys, review) and nine React views. If the nine React tabs show "Extension bundle unavailable" the bundle was missing when the renderer ran (`skill/assets/explorer.html:194`; cause and fix in `docs/developer/troubleshooting.md`).

Browser storage: theme and review decisions (`skill/assets/explorer.html:39-40`) and Living ERD layouts (`packages/explorer/src/living-logic.ts:72`) are kept in `localStorage`, keyed by `project.key`. Schema City has no camera persistence today (`packages/explorer/src/City.tsx` never touches `localStorage`); it arrives with W05 (F08). `localStorage` is per origin, so state saved while the file is open over `file://` is not visible when the same artifact is served over `http://`, and vice versa. Whether two different local files share one `file://` origin is browser-dependent (to be validated per supported browser); treat state saved from `file://` as non-portable. Caveat C13 applies:

> Browser storage holds convenience state only: theme, layouts, camera, and local decisions. It is not a team review database. Every stored key is scoped by the project's stable key (and, where the data depends on the schema, by the snapshot fingerprint) so that different projects and environments never read or overwrite each other's state.

## 3. Optional loopback live mode (`serve_explorer.py`)

`packages/explorer/server/serve_explorer.py` serves one built artifact over HTTP on the loopback interface and, when a dialect is selected, enables two read-only endpoints (`POST /api/profile`, `POST /api/subtree`) that the Row fan-out, Column table, and Normalization lens views can call. Caveat C14 governs every use of it:

> The product never discovers or connects to a database implicitly, and never to production to make a view look populated. Live access uses only a connection the user explicitly selected, opened read-only with bounded queries, and a metadata request never authorizes scanning customer rows.

### 3.1 Create a SQLite database from the fixture seed

`fixtures/sql/sqlite/seed.sql` is generated from the `medium-measured` fixture (`scripts/generate-fixtures.mjs:1021`; header comment at `fixtures/sql/sqlite/seed.sql:1`). `medium.json` and `medium-measured.json` share the same 160 table ids, so either snapshot passes the profiler's identifier validation; the examples below use `medium-measured.json` because its declared row counts describe the seeded data (`fixtures/README.md`). Create the database file somewhere that is ignored or outside the clone; `dist/` works because it is ignored:

```sh
python -c "import sqlite3,sys; c=sqlite3.connect(sys.argv[1]); c.executescript(open(sys.argv[2],encoding='utf-8').read()); c.commit(); c.close()" dist/fixture.sqlite fixtures/sql/sqlite/seed.sql
```

The profiler never creates a database: `--database` must name an existing file (`packages/explorer/server/schema_profiler.py:193-195`, `resolve(strict=True)`), and it is opened read-only with `?mode=ro` and `PRAGMA query_only = ON` (`:196-199`).

### 3.2 Start the server

```sh
python packages/explorer/server/serve_explorer.py \
  --html dist/backend-buddy.html \
  --schema fixtures/schemas/medium-measured.json \
  --dialect sqlite \
  --database dist/fixture.sqlite \
  --snapshot-output dist/profiled-medium-measured.json \
  --port 8765
```

Flags (`packages/explorer/server/serve_explorer.py:18-25`): `--html` and `--schema` are required; `--port` defaults to 8765; `--dialect sqlite|postgresql` enables live mode; `--database` (SQLite file) or `--dsn-env` (the name of the environment variable holding a PostgreSQL DSN, never the DSN itself); `--snapshot-output` writes the profiled graph after each `/api/profile`; `--include-sample-values` opts in to at most three bounded sample values per column. The snapshot output must be a different file from every input (`:27-30`, `snapshot_io.validate_output`). Without `--dialect` the server serves the artifact unchanged with the API disabled.

The server prints its URL, for example `http://127.0.0.1:8765/ (read-only connection enabled)` (`:114`).

### 3.3 Open exactly `http://127.0.0.1:<port>/`

Type the printed address. The server binds `127.0.0.1` (`serve_explorer.py:113`) and accepts only requests whose `Host` header equals `127.0.0.1:<port>` (`:42`, `:58-59`, `:62`); `POST` additionally requires `Origin: http://127.0.0.1:<port>` (`:75`). `http://localhost:8765/` returns 404 by design, and the test suite pins that (`packages/explorer/server/test_explorer_http.py:206`). Work package S03 adds `--bind` and `--allowed-hosts` with `localhost` allowed by default; until then use the numeric address.

In live mode the served copy, and only the served copy, gets `connect-src 'self'` and a per-process capability token injected before the schema data (`serve_explorer.py:66-70`). The file on disk keeps the offline CSP. The status footer shows "Live read-only connection" instead of "Snapshot only".

Requests: one read-only job at a time (`409` otherwise, `:89-90`); bodies limited to 64 KiB (`:83-84`); the profiler caps apply (`docs/reference/limits-and-caps.md`, section A1). Database errors are redacted to a fixed message so DSNs and sampled values never reach the browser (`:109-111`).

### 3.4 PostgreSQL instead of SQLite

Requires psycopg 3 (`packages/explorer/server/requirements.txt`). Put the DSN in an environment variable and pass its **name**:

```sh
export BB_READONLY_DSN='host=... dbname=... user=... password=...'
python packages/explorer/server/serve_explorer.py --html dist/backend-buddy.html --schema <snapshot.json> --dialect postgresql --dsn-env BB_READONLY_DSN --port 8765
```

The DSN must contain `host`, `dbname`, `user`, and `password` explicitly; `service` and `passfile` credential discovery are rejected (`schema_profiler.py:208-214`). The connection is opened with `default_transaction_read_only=on` and `statement_timeout=5000` (`:215-216`). Use a database and role you control; the fixture PostgreSQL arrives with the O01 dev overlay.

### 3.5 Batch profiling without a server

`packages/explorer/server/profile_snapshot.py` profiles a snapshot in one pass and writes a new file: `--schema`, `--output`, `--dialect`, `--database` or `--dsn-env`, optional `--tables`, `--limit` (default 10,000, then clamped by `MAX_ROWS`), `--include-sample-values` (`profile_snapshot.py:12-19`). Build the artifact from the profiled output afterwards with `--schema`.

## 4. Compose flow: available after O01

Not runnable today; recorded so the target is visible. Work package O01 (approved plan, Phase 2) delivers `deploy/Dockerfile`, `deploy/compose.yml` (services `db`, `migrate`, `api`, `worker`; secrets `backend-buddy_master_key`, `backend-buddy_db_password`), `deploy/compose.dev.yml` (Vite HMR proxying `/api`, API `--reload`, a fixture PostgreSQL seeded from `fixtures/sql/pg`, `BB_ALLOW_PRIVATE_TARGETS=true`), `deploy/compose.qa.yml` (Playwright image), `deploy/.env.example`, and `deploy/.dockerignore`. The intended commands:

```sh
cp deploy/.env.example .env                                          # placeholders only; fill in locally, never commit
docker compose -f deploy/compose.yml up                              # production-shaped stack
docker compose -f deploy/compose.yml -f deploy/compose.dev.yml up    # dev overlay with HMR and fixture PostgreSQL
curl -fsS http://127.0.0.1:<api-port>/readyz                         # CTQ-15: ready in under 5 minutes from a clean machine
python -m app.bootstrap                                              # first owner account, one-time password (A02)
```

Until O01 merges, sections 1-3 are the only way to run the product, and the live server cannot be reached through a published container port because of the loopback bind and exact `Host` match described in 3.3 (S03 precedes O01 for this reason). Operator-facing instructions will live in `docs/operations/deployment.md` and `docs/operations/rollback.md` (D06/O01).
