# `packages/contract`

The SchemaGraph contract, machine readable. `schema-graph.v1.json` is the single source of truth
for the exchange format adapters emit, the artifact renders, and the API stores.

## What lives where

| Concern | Path | Generated? |
|---|---|---|
| JSON Schema (draft 2020-12), contract version 1 | `packages/contract/schema-graph.v1.json` | no, hand written |
| TypeScript interfaces the nine views import | `packages/explorer/src/contract.generated.ts` | yes, `npm run contract` |
| Field tables in the skill reference | `skill/references/schema-contract.md`, between `<!-- generated:fields:start -->` and `<!-- generated:fields:end -->` | yes, `npm run contract` |
| Python validator | `packages/profiler/bb_profiler/contract.py` | no |
| Shared valid and invalid corpus | `fixtures/contract/{valid,invalid}` and `fixtures/contract/v1/{valid,invalid}` | yes, `npm run fixtures` |
| Prose contract, compatibility policy, id forms | `docs/architecture/schema-graph-contract.md` | no |

Corpus documents are generated by `scripts/generate-fixtures.mjs` from word lists, never copied
from a real schema, and they live in one place under `fixtures/` so both validators walk the same
tree. Add a case to the generator, then run `npm run fixtures`.

## Two stages, one oracle

Validation has two stages and they are not interchangeable:

1. **Structural** -- this JSON Schema: types, enumerations, required fields, length caps, numeric
   bounds. It rejects a malformed or oversized document before any of it is used.
2. **Semantic** -- `normalize()` in `skill/scripts/build_explorer.py`: unique table ids, unique
   column names, primary-key subsets, index and unique column membership, declared-target
   resolution, duplicate relationship pairs, composite-group consistency, inferred dedupe. It is
   the only implementation of those rules and is imported, never copied
   (`docs/architecture/adr/ADR-0003-backend-fastapi-and-contract-oracle.md`, decision 4).

`bb_profiler.contract.validate_document()` runs them in that order and returns the normalized
document. `ContractError` subclasses `ValueError`, so callers that already handle `normalize()`'s
errors need no change.

## Wire form versus normalized form

The schema describes what an adapter may **send**, including the legacy forms the contract keeps
accepting: `"True"`/`"False"` and `0`/`1` for `pk`, `index`, `unique`, and a boolean, `null`, `""`,
`"True"` or `"False"` for `nullable`. The generated TypeScript describes the document **after**
`normalize()` has coerced those forms, because that is the only shape a view ever sees.

Where the two differ, the schema records the TypeScript form in `x-tsType`, and each definition's
`x-typescript` annotation carries the interface name, the property set `normalize()` guarantees
(`required`), and the index signature to emit. Both are vendor extension keywords: a validator
ignores them, and only `scripts/gen_contract.mjs` reads them.

## Changing the contract

```sh
npm run contract          # regenerate the TypeScript interfaces and the reference field tables
npm run contract:check    # fail on drift; also runs inside npm test
npm run typecheck         # the nine views must compile untouched
npm test                  # both corpora, both sides
```

Additive changes only within major version 1: a new optional field or a new enumeration value with
a documented default, and the `MINOR` part goes up. Removing or renaming a field, tightening a
type, or changing the meaning of `kind`, `rowCount` or `constraintId` is a major change, which the
Python side rejects and which needs a migration note. The full policy is
`docs/architecture/schema-graph-contract.md` section B5.
